Checked with `lc.py src/ultima/work/ul_03e9.C --exe build/ultima/ULTIMA.EXE --syms src/ultima/ultima.syms`
(gamedata/ULTIMA.EXE is the enveloped original; build/ultima/ULTIMA.EXE is byte-identical in the game part).

## 4. Data layout (for integration)
`--data 124` matches 0124-02B8 (the three bitmaps then the first six literals, in order of use). At 02B9 the
original has the picture rows and the pointer tables D_3262/D_4320/D_43A0 (and D_2F71, D_2FF3, D_3038 inside
the row area) defined between functions; then the later literals (43C0 ...) come after those tables, i.e.
the picture data was defined between F_0586 and F_0A27 (after F_0586's literals, before F_0A27's). Needs
tools/cdata.py to draft those definitions.

## 5. Compiler lessons
- `unsigned long s; s >> 1` gives shr/rcr (long gives sar); `s / w` and `s % w` with int w both call CXD22 when
  s is unsigned long (long gives CXD22 for / and CXD33 for %).
- A function with one local that makes no calls (F_0722) had its local at [bp+2], frame 4: a dummy first local
  `int u, n;` reproduces it. F_08BF with two locals (b, a) and an expression temp gets frame 0xA with a at +8.
- Statement order decides which delayed store comes first: `y1=0x14; y2=0x53; col=9;` before the call.
- `do {...} while (++j < 0x113)` gives `inc j; mov ax,j; cmp ax,..`.
- `argv[1][0]` (unsigned char **argv) gives `mov bl,[si]; xor bh,bh`, `*argv[1]` does not.
