## Compiler lessons
- Locals do not start at bp+2: the compiler reserves a variable number of 2-byte temp slots at the bottom (6 bytes in F_7F0F/F_81FC/F_7C31, 4 in F_8479). Do not add dummy locals; just declare the real ones in order.
- `jne +3; jmp far` pairs mean the skip target is more than 127 bytes away, not a different construct. A void `return;` in an if is an inline epilogue; a shared epilogue jump means nested if/else (F_7C31, F_7D6B: else-if chains; F_873D, F_8A04: a single big `if (a && b && c && d)` / nested ifs). Writing `if (...) return;` gives the wrong code.
- Common-subexpression reuse across `if` condition and body (temps at [bp] / [bp+4]) happens when the same array expression occurs again; in F_8A04 the original test was part of one `&&` chain with the three tile tests, which prevents it from sharing with the body? (match came from `if (t != 1 && t != 2 && t != 8 && cell.b == -1) {...}`).
- `if (x || y || !hit)` with the miss branch first matched; `hit == 0` or reordering did not.
- `(a > b ? a : b) <= v` then `return v; return 0;` matches; `return max > v ? 0 : v` does not (v is loaded into BX first).
- `q[n] = i; n++;` gives store-then-inc; `q[n++] = i` gives inc first.
- Chained store order: `f = D_2086 = 0` stores D_2086 first; `D_204E = D_204A = D_8B9C = 0` stores D_8B9C first (rightmost assigned first).
- A store followed by an immediate reload (`mov [k],ax; mov ax,[k]; cmp ax,1`) means a do-while loop condition after a label: F_8C20 is `do { do {...} while (t != F_40FE(x,y)); k = F_C2AF(x,y,1); } while (k != 1 && k != 2);`.
- Passing a 3-D array name as an argument: `(char *)D_8BAE` (a cast) made the compiler load the address into AX first like the original; a bare `D_8BAE`, `&D_8BAE[..]`, `D_8BAE + 0` did not.
- Names whose data lie inside a larger symbol (D_36F8 etc.) can be reached as `D_0FD8 + n` via #define; lc.py accepts it.
