## 4. Compiler lessons / oddities
- .syms names D_07FA_S for both 07FA and 10FA, so an `extern int D_07FA_S[]` resolves to 10FA (lc.py
  reports a wrong target). Worked around by declaring `extern struct { int a[20][20]; int b[18][21]; } D_04DA;`
  and using D_04DA.b (07FA = 04DA + 800). Replace by the real definitions on integration.
- Dummy locals are not needed: a function with a few locals and calls simply has the frame the locals ask
  for ([bp+0] is only the compiler temp). Declare exactly the locals actually used.
- A field at offset 0xA of the 0xC-byte ship record is `dir`: `D_26CA[BX]` with BX including +0xA is
  o[s].dir (not x). lc.py's target check caught this.
- Initial zeroing `a=0;b=0;c=0;d=0;` is stored in reverse order by the compiler; write the statements
  in reverse (d first) to get the stores of slot 8,A,C,E in increasing order.
- `F_3E85("inuse.u1", (int)D_2058, 0x334)`: the `(int)` cast makes the array address come first in AX
  (as in mo_12ec.C); without it the constant is loaded first.
- `x*2*5 + 0xA5 - 0x23 + 2` is not constant-folded by Lattice (ADD, SUB, INC, INC).
- `i = 0; while (!F_413C(0) && i++ < 10000);` gives the `inc` after the load (compare of old value).
- F_413C is `unsigned char` (xor ah,ah in F_14E5 where j = F_413C(0)); F_0F3B still gets `test al,al`.
- abs() inline: `#define ABS(x) ((x) < 0 ? -(x) : (x))` reproduces the neg/branch forms (F_09AF, F_165C).
- Nested ifs `if (c) { a = ..; if (a) { ... if (a == 2) {...} } }` give the shared epilogue / long jumps of F_09AF.
